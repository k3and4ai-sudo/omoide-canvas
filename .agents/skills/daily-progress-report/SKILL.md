# Daily Progress Report & Session Wrap-up Skill (終了処理スキル)

本スキルは、開発作業の終了時（「今日はここまで」「終了処理をお願い」など）に呼び出され、**作業成果の確実な記録・引き継ぎ**と**次回セッションのスムーズな再開（コールドスタート防止）**を自動化するための手順書です。

---

## 終了処理の基本フロー

終了処理を依頼された際、エージェントは以下のステップを順に実行してください：

### Step 1: 本日の改修差分・状態の確認
1. `git status` および `git diff --stat` で、本日作成・修正されたファイルの一覧と差分を確認する。
2. 動作中のバックグラウンドタスク（devサーバー、トンネル等）の稼働状況を確認する。
3. 未解決の課題・エラー・ログ出力（直前に発生した不具合の原因）を整理する。

### Step 2: 進捗報告書ファイル（`YYYY-MM-DD_本日最終進捗報告.md`）の作成
プロジェクト直下に以下の標準テンプレートに沿って報告書を新規作成（または追記更新）する。

```markdown
# YYYY-MM-DD 本日最終進捗報告 ＆ 次回再開手順書

## 1. 本日の総括と成果サマリー
- 本日対応した主要テーマと達成度を簡潔かつ具体的に要約。
- プロジェクト全体における現在の立ち位置（フェーズ、ステップ）を明記。

## 2. 本日達成された重要マイルストーン
### ① [機能・課題名]
- **課題・背景**: どのような不具合や要求があったか
- **実施した対策**: どのファイルをどのように修正・実装したか
- **検証結果**: 実機・テストスクリプトでの動作確認結果

### ② [機能・課題名]
...

## 3. 本日の改修・新規作成ファイル一覧
| ファイルパス | 変更区分 | 改修内容・役割 |
| :--- | :---: | :--- |
| [`path/to/file`](file:///absolute/path/to/file) | 新規 / 更新 | 変更の要約 |

## 4. 残課題と根本原因の分析（次回最優先対応）
- 直前の操作で発生した事象（エラーログ、ステータスコード、再現手順）
- 特定された根本原因
- 次回講じるべき具体的解決策

## 5. 次回再開時の手順（チェックリスト）
次回開始時にそのまま実行できるコマンドと確認項目を記載。

### Step 1: サーバー起動・環境準備
```bash
# 起動コマンド
```

### Step 2: 動作確認チェック項目
- [ ] 確認項目1
- [ ] 確認項目2
```

### Step 3: 安全な終了処理の実行
1. バックグラウンドで不要となった一時テストタスクがあれば停止する。
2. 次回すぐに開発・テストを再開できるよう、設定ファイル（`.env`）や仮想環境（`.venv`）の整合性を保つ。
3. ユーザーへ、本日の労いとともに進捗報告の要約と次回再開手順を提示する。
